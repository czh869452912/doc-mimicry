# PRD Document Skill

## What To Learn From Examples

Learn:

- Section order.
- Heading granularity.
- Background, goals, and non-goals rhythm.
- Metric and acceptance criteria style.
- Table, list, and numbering patterns.
- Risk, dependency, and decision framing.

Do not copy:

- Project-specific content.
- Specific metric values.
- Proper nouns.
- Original sentences.

## Typical PRD Shape

A PRD often includes:

- Background.
- Goals.
- Non-goals.
- Users and scenarios.
- Requirements.
- Interaction or process details.
- Metrics and acceptance criteria.
- Risks and dependencies.
- Open questions.

If the user brief is insufficient, state assumptions or ask questions instead of inventing key facts.

Before export, read `checklists/quality.yaml` and write results to `reviews/checklist_result.md`.
